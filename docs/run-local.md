# Локальный запуск — draft

Первый локальный срез принят на синтетике, включая физический перезапуск тестовой PostGIS. Живое подключение Fintraffic проверяется отдельно. API показывает сохранённые позиции; без них список будет пустым. Не используйте проект как публичный сервис.

1. Создайте локальное окружение Python 3.12 и установите зависимости по [инструкции API](api/v1.md). Скопируйте `.env.example` в `.env`, задайте собственные значения вне Git и запустите PostgreSQL/PostGIS командой `docker compose up -d db`. В Compose закреплён образ `linux/amd64`; на Apple Silicon Docker запускает его через эмуляцию.
2. Установите `SFD_DATABASE_URL` для владельца и выполните `.venv/bin/python -m shadow_fleet migrate`. Создайте отдельную роль только для чтения с доступом к `source`, `source_state`, `latest_position`, `position_history`, как описано в [API v1](api/v1.md); задайте её адрес в `SFD_API_DATABASE_URL`. Значения `.env` автоматически загружает Docker Compose, но Python-процессу переменные нужно передать отдельно.
3. Запустите `.venv/bin/python -m shadow_fleet api` и в другом терминале `cd web && npm ci && npm run dev`. Откройте адрес, выведенный Vite. Оба процесса привязаны к localhost; прокси UI направляет `/v1` на порт 8000.
4. Остановите процессы клавишами Ctrl+C и контейнер командой `docker compose stop db`. Это не удаляет volume. Для удаления используйте только явно созданное тестовое окружение, предварительно убедившись, что в нём нет нужных данных.

Коллекция [Postman](../postman/README.md) использует тот же локальный API. `python -m shadow_fleet collect` подключается к настоящему Fintraffic; не запускайте его как тест без отдельного согласия на живую пробу.

## Уже подготовленное окружение на этом Mac

Созданы локальный `.env` с правами доступа только владельца и Docker volume `shadowfleetdetector_pgdata`; пароль в Git не добавлен. Применена миграция, создана отдельная роль `sfd_reader`, проверено, что она может читать и не может удалять позиции. Для следующих запусков API из корня проекта загрузите переменные в текущий терминал:

```sh
set -a
source .env
set +a
.venv/bin/python -m shadow_fleet api
```

В другом терминале: `cd web && npm run dev`. `SFD_API_PROXY` позволяет изменить адрес API, на который Vite направляет `/v1`. Сборщик запускается отдельно через `.venv/bin/python -m shadow_fleet collect`; эта команда подключается к настоящему Fintraffic и не была запущена в ходе тестирования. Перед применением к реальным данным остаются незакрытые проверки из [приёмки](development/acceptance.md).

История — опциональная часть [v0.2 draft](api/history.md): примените миграцию 002 и добавьте право SELECT на `position_history` существующей роли API. Перед стартом сохранения учитывайте локальное дисковое пространство; семидневное окно не задаёт фиксированный размер БД.

## Проверка всех локальных этапов

Из корня проекта, после установки Python-пакета и `npm ci` в `web/`, с работающим Docker и установленным Chrome:

```sh
.venv/bin/python scripts/accept_local.py
```

Команда запускает одноразовую PostGIS на свободном порту, прогоняет pytest и Ruff, загружает синтетическую точку, затем проверяет Chrome через отдельный FastAPI с ролью только для чтения и синтетическим досье. В конце выполняет TypeScript и сборку, а контейнер удаляется. Рабочий `.env` и рабочая БД не используются. Если выполнение принудительно прервано и остался контейнер `sfd-release-*`, удаляйте только экземпляр этого прогона.

[История](api/history.md) отображает отдельные точки и [сводку качества](api/quality.md). [Досье](api/dossier.md) по умолчанию пусто; при необходимости настройте собственный локальный каталог. Историю и досье можно испытать без реального источника в сквозном тесте.
