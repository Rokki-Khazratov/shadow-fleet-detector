# Локальная приёмка и история наблюдений — draft

Для исполнения используем существующий план v0.1, pytest и отдельную БД. История — первый шаг после v0.1; это рабочий выбор для продолжения, а не ранее согласованная продуктовая спецификация.

1. Закрыть приёмку v0.1: синтетическая запись → физическая остановка тестовой PostGIS → 503 → восстановление БД → сохранённая позиция и новый epoch. Повторить исходные Python и браузерные проверки. Реальный Fintraffic и публикация вне этого прогона.
2. Добавить миграцию 002 и опциональную историю в writer: `collect --history`, семь суток, один результат сверки на источник/MMSI/секунду, тот же merge и та же транзакция. Не менять миграцию 001, не переносить данные автоматически. TTL проекции остаётся сутки. В выключенном режиме writer не добавляет историю; уже накопленная история продолжает удаляться по TTL при запущенном сборщике.
3. Добавить API одного источника и MMSI: явные UTC границы окна, до 1000 точек по возрастанию времени, признак усечения и атрибуция. Отдельное право SELECT. Разрывы — отсутствие сохранённых наблюдений; не интерполировать и не сопоставлять идентичности.
4. Проверить миграции, повтор/конфликты, атомарность, разделение TTL, права чтения и границы API на синтетике. Задокументировать запуск, ограничения и следующий шаг (отображение истории на карте).
