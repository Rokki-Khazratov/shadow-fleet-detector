## Продолжение: Postman, сборщик и карта — 2026-11-14

Коллекция из `postman/` импортирована в персональное рабочее пространство Postman; отображаются все семь запросов. MCP настроен, но авторизация OAuth отдельно не подтверждена.

Добавлены промежуточные блоки сборщика: ограниченное чтение и декодирование snapshot, очередь с watermark и учётом неподтверждённых сообщений, обработка retained, а также commit snapshot и префикса в одной транзакции. Синтетическая интеграция с PostGIS проверяет merge REST/MQTT и конфликт. Это не полноценный collector: сетевой REST/MQTT transport, reconnect, таймауты и lifecycle ещё не реализованы; гонку переполнения во время commit ещё необходимо разрешить.

Создан черновой браузерный клиент `web/` с MapLibre и техническим фоном, выбором из списка и карточкой. Проверены типы, сборка, синтетические браузерные сценарии, в том числе мобильная ширина; для синтетического desktop-снимка визуально подтверждена отрисовка точки. Дополнительные сценарии восстановления, отмены устаревших запросов, доступности и полной сквозной приёмки остаются открыты. Установлен Node 26.13.0 (LTS Lithium); версия среды зафиксирована для локального клиента.

## Сетевой сборщик — 2026-11-14, проверка продолжается

Добавлены bounded HTTP snapshot и MQTT WebSocket/TLS transport на `httpx` и `paho-mqtt`, lifecycle с повторным созданием writer/epoch, ограничением очереди, heartbeat, reconnect, Retry-After и корректной остановкой. Команда `python -m shadow_fleet collect` предназначена для локального запуска. Тесты используют fake transport, синтетические сообщения и временную PostGIS; реальная сеть Fintraffic не вызывалась.

Это ещё не полная приёмка: исправлены и проверены откат при переполнении до commit, ограничение сетевого ожидания и лимиты транзакции PostgreSQL. Часть отказных и нагрузочных сценариев, развёрнутая приёмка и проверка реального источника ещё остаются открыты. API и карта не следует считать проверенными с реальным потоком. Postman OAuth подтверждён владельцем: команда авторизации сообщила `Successfully logged in`.

## Продолжение: локальная инфраструктура и синтетический поток — 2026-11-14

OAuth Postman MCP успешно завершён. Импортированная коллекция проверена в приложении запросом к локальному API (`200 OK`). Созданы локальные `.env` (не в Git) и отдельная база проекта с read-only ролью API. API и Vite запущены на localhost; реальный сборщик не запускался. Docker-образ PostGIS закреплён по digest; проверена платформа `linux/amd64` на ARM через эмуляцию.

Синтетический MQTT через fake transport прошёл collector → PostGIS → API → браузер и открыл карточку. 60-секундная нагрузка в памяти: 6 000 сообщений, 1 000 ключей, peak queue 250, max RSS 43 204 608 байт; БД и сеть в этот замер не входили. Подробности и оставшиеся проверки — в [приёмке](acceptance.md). Node 26.13.0 подтверждён как LTS Lithium и закреплён в `web/.nvmrc`.

## Независимое ревью и исправления — 2026-11-14

В независимой проверке найдены и исправлены: устаревший heartbeat во время синхронизации, закрытие MQTT epoch при разрыве во время REST/commit, экспоненциальный backoff после последовательных разрывов, heartbeat при открытии writer и сохранение предыдущих времён доставки при раннем сбое нового epoch. Для всех сценариев добавлены проверки; `starting` без heartbeat остаётся допустимым до первого запуска сборщика.

## Синтетическая сквозная приёмка — 2026-11-14

Playwright прошёл единый сценарий snapshot → push → duplicate → conflict → имитированный disconnect → ошибка SQL и rollback → новый epoch → TTL → восстановление интерфейса при 503. Сценарий использует только отдельную базу `_test`; ошибка SQL моделирует сбой записи, но не физическое выключение PostgreSQL. Детали и повторение — в [приёмке](acceptance.md).
