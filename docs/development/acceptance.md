Повтор сквозного теста требует **отдельной временной** базы с именем `_test`, миграции и переменной `SFD_TEST_DATABASE_URL`. Скрипт `.venv/bin/python tests/integration/seed_browser.py` добавляет синтетический сигнал в эту базу. Запустите API на порту 58123 с read-only DSN к той же базе, затем в `web/`: `SFD_REAL_API_TEST=1 SFD_API_PROXY=http://127.0.0.1:58123 npm run test:e2e -- integration.spec.ts --workers=1` вместе с `SFD_TEST_DATABASE_URL` для изолированной базы. Второй сценарий изменяет только `_test` базу. Никогда не направляйте тесты и бенчмарки на рабочую БД.

Независимое ревью отметило, что до первого запуска сборщика начальное состояние остаётся `starting` с пустым heartbeat. Это согласовано с контрактом: для отсутствующего `source_state` требуется `starting` и null-времена. После запуска writer heartbeat записывается, и его устаревание приводит к `degraded`.

Команда для отдельной физической проверки: запустите закреплённый образ PostGIS из `compose.yaml` с именем `sfd-phase1-20261115`, портом `127.0.0.1:55449:5432`, тестовой БД `sfd_phase1_test` и тестовыми именем и паролем `sfd_test` (контейнер без `--rm` для остановки и повторного старта). Из корня проекта выполните `.venv/bin/python tests/integration/check_database_restart.py`. Для этой команды рабочая БД не используется.
