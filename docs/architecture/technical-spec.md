# ТЗ v0.1 — региональная карта наблюдений

**Статус: draft на ревью.** [Системный дизайн](system-design.md) · [Модель БД](database-design.md) · [План разработки](technical-plan.md).

Первый срез позволяет открыть карту Финского залива, увидеть доступные позиции Fintraffic, выбрать сигнал и понять, где и когда он наблюдался. Начальный центр карты — Финский залив; фильтр ограничивается окном просмотра, отдельный фильтр по типам судов не требуется. Приложение принимает позиции всех типов, которые отдаёт источник. Срез сохраняет направление глобальной карты, не обещая глобальные данные.

Доказательная база: [замеры REST/MQTT и Kystverket](../research/ais-transport-comparison.md) и [критерии готовности](../research/development-readiness.md). Объём и параметры ниже предложены для первого этапа. Результаты коротких проб не задают SLA.

| ID | Требование | Проверка приёмки |
|---|---|---|
| R01 | Карта показывает валидные позиции Fintraffic в viewport, включая позиции без известного типа судна. | Фикстуры внутри/за пределами bbox, bbox через антимеридиан, граница ±180°, невалидная широта и неизвестный тип. |
| R02 | Выбор маркера показывает MMSI, позицию, время записи, возраст и источник. | REST-время в мс и MQTT-время в с видны как UTC. AIS-секунда 0–63 не становится датой. MMSI передаётся строкой, не выдаётся за идентификатор корпуса. |
| R03 | При старте и восстановлении поток подписывается до снимка; валидные MQTT-обновления не теряются при сверке. | Сценарий: MQTT 12:00:02, затем приходит REST 12:00:01.900; позиция остаётся в секунде 02. Повтор и запоздавшее сообщение не откатывают маркер. |
| R04 | Приложение показывает различие между временем позиции, состоянием источника и отсутствием наблюдений. | На разрыве источника маркеры остаются до TTL; возраст растёт. Нулевой результат не выдаётся за отсутствие судов. Неуспешный снимок не заменяет последнюю картину пустой. |
| R05 | Источник и лицензия видны в карте и ответах API; наружу выходят только нормализованные поля. | Проверить текст Fintraffic и ссылку CC BY 4.0; bbox-запрос не обращается к поставщику и не выводит payload. Права тайлов — отдельно от данных. |
| R06 | REST и MQTT сообщения проходят одинаковые правила координат и специальных значений. | Невалидная точка отклоняется; 511 heading, 360 COG и 102.3 SOG преобразуются в null; валидный ноль скорости сохраняется. |
| R07 | Приложение восстанавливается после перезапуска и повторного подключения без потери уже зафиксированного состояния. | Проверка restart с неполной сверкой, переполнением буфера и 429; последняя подтверждённая позиция остаётся, состояние degraded видно. |
| R08 | Первичный UI и API не классифицируют суда как теневые по AIS или наличию санкций. | Нет таких полей и меток в ответах и UI первого среза. Дальнейшие аномалии, внешние утверждения и идентичность требуют отдельных моделей и проверок. |

### Предлагаемые измеримые параметры

| Параметр | Значение для v0.1 | Как проверить |
|---|---|---|
| Возраст | fresh ≤5 минут, stale >5 минут, скрытие по истечении 24 часов с времени записи | Управляемые часы и три граничных значения; будущая метка >60 с отклоняется, сдвиг (0,60] с помечается полем clock_skew и возраст ограничивается нулём |
| Обновление UI | Запрос нового viewport сразу, по таймеру каждые 5 с, только один активный запрос; отмена при смене bbox | После смены viewport старый ответ не перекрывает новый; сеть не получает бесконечный хвост запросов |
| Картографический ответ | До 2 000 маркеров, явный признак truncated | Фикстуры с 2 001+ ключами в bbox; стабильный порядок |
| Локальная цель API | p95 ≤300 мс на прогретой выборке 5 000 текущих позиций, один клиент, 100 запросов | Указать окружение, результат и размер ответа; без обещания production SLA |
| Хранение | По умолчанию только текущие позиции с TTL 24 ч; без сырых треков, без истории и без enrichment | TTL-job удаляет просроченные строки, API исключает их даже до очистки |

Первый срез: локальный запуск, без аккаунтов, внешней публикации и платных ключей. История маршрута, несколько источников, слой доказательств, история наблюдений и публичное развёртывание — отдельные этапы. Первую версию карты можно проверить на нейтральной подложке, пока поставщик публичных тайлов не выбран.
