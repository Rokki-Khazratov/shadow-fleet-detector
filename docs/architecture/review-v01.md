# Ревью проектного пакета v0.1

Дата: 2026-11-14. Статус: **draft**, ревью документов; приложение не реализовано. Проверены ТЗ, системный дизайн, модель БД, план работ и структурная корректность трёх HTML-схем.

## Исправления

| Пробел | Уточнение | Документ |
|---|---|---|
| Будущая метка времени помечалась только на словах | clock_skew в БД и JSON, точные границы допуска и часы сравнения | ТЗ, БД, системный дизайн |
| Результат одинаковых REST/MQTT сообщений мог зависеть от доставки | Одинаковое содержимое проходит общий tie-break; определены received_at и сохранение конфликта | БД |
| Ожидание опустошения очереди могло никогда не закончиться | Фиксированный watermark, атомарный префикс и последующие пачки | Системный дизайн |
| Неясное здоровье после REST без MQTT | Условия live, retained-only, дубликаты и отсчёт таймаута от SUBACK | Системный дизайн |
| Неограниченная длительность отдельных операций | Таймауты подключения, записи, бюджет TTL; Retry-After имеет приоритет | Системный дизайн, БД |
| Неоднозначная обработка ±180 | Диапазоны, включённые границы, целый мир и нулевая ширина | Системный дизайн |
| Удаление последнего ответа противоречило сохранению карты при сбое | Последняя карта остаётся с явной отметкой устаревания | Системный дизайн |
| Повтор миграции был неоднозначен | Журнал версий runner, а не повтор SQL | План |

Добавлены задания на проверку каждого исправления. Это критерии будущих тестов, а не доказательство работающей реализации.

## Выполненная проверка

- Структурный self_check из diagram-design: architecture.html, reconcile.html, data-model.html — успешно.
- Проверены относительные Markdown-ссылки проектного пакета и корректность JSON-примера API.
- Схемы остаются обзорными: точные поля, переходы и ограничения определяются текстовыми контрактами.
- Визуальная проверка в браузере не завершена: локальный headless Chrome завершился с кодом 134 до создания снимка. Структурный self_check не заменяет проверку читаемости.

## Что остаётся открытым

1. Региональный срез, стек и пороги остаются предложениями. Глобальный продукт и доказательный слой теневого флота — последующие этапы, не отменённые требования.
2. Короткие пробы источника не доказывают суточное покрытие, отсутствие потерь и работоспособность восстановления. Нужны ограниченные длительные наблюдения с агрегатами.
3. Значения лимитов JSON, максимальная память процесса и реальная длительность bootstrap требуют измерений. Лимит байтов payload не равен лимиту RSS.
4. До реализации нужны точные golden fixtures канонической сериализации и перечень допустимых форм входного JSON; до публичного запуска — повторная проверка прав на данные и выбор тайлов.
5. Приёмка конкурентных записей, TTL, аварий, производительности и интерфейса пока не выполнялась: соответствующего приложения ещё нет.

Следующий шаг фундамента: специфицировать фикстуры и матрицу отказов, затем проверить источник длительной ограниченной пробой. Начало разработки требует отдельного решения владельца.
