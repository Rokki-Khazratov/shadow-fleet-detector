# План реализации v0.1 — первый региональный срез

> Draft на ревью. Исполнять только после решения о старте. Для пошаговой реализации использовать executing-plans или subagent-driven-development по согласованному режиму.

**Цель:** локальная карта текущих наблюдений Fintraffic с честным отображением свежести и состояния потока.
**Архитектура:** один сборщик сверяет REST и MQTT; PostgreSQL/PostGIS сохраняет проекцию; API обслуживает карту и карточку наблюдения.
**Стек (предложение):** Python / FastAPI / Paho / psycopg, PostgreSQL/PostGIS, MapLibre / TypeScript.
**Контракты:** [ТЗ](technical-spec.md), [системный дизайн](system-design.md), [модель БД](database-design.md), [доказательная база](../research/development-readiness.md).

Ограничения первого среза: один источник, локальное окружение, без сырых треков, истории, платных ключей, аккаунтов, публичного запуска и меток «теневой флот». Все пути ниже — будущие. До начала согласовать объём, стек и продуктовые пороги из ТЗ. Числа из проб — наблюдения; пороги — предложения.

### Этап 1. Нормализация

Будущие файлы: `src/shadow_fleet/fintraffic.py`, `src/shadow_fleet/model.py`, `tests/test_fintraffic.py`, `tests/fixtures/ais/`. Входы: словарь REST feature и пара topic + MQTT payload; выход: NormalizedPosition или типизированная причина отклонения. Без сетевого доступа и часов машины в unit tests.

- [ ] Собрать синтетические REST/MQTT пары с одной секундой времени, нулевыми значениями, отсутствующими углами, дублем MMSI в feature vs properties, ошибочными координатами, будущим временем на 60/61 с.
- [ ] Проверить, что нормализатор возвращает совпадающий bucket при с/мс, сохраняет precision и UTC формат, отвергает несовпадающие ID и неверные точки; sentinel → null. Запустить `python -m pytest tests/test_fintraffic.py`; fixtures не содержат реальных треков.
- [ ] Зафиксировать каноническую сериализацию для fingerprint: JSON-массив фиксированного порядка [lon,lat,sog,cog,heading], все числа привести к float с положительным нулём, валидные конечные числа без NaN/Inf, null для отсутствующих полей; Python JSON compact UTF-8. Сопоставить байты для эквивалентных REST/MQTT значений.

### Этап 2. Детерминированная проекция

Будущие файлы: `db/migrations/001_v01.sql`, `src/shadow_fleet/store.py`, `tests/integration/test_store.py`. Вход: пачка NormalizedPosition + epoch; выход: commit и счётчики применённых/игнорированных/конфликтных. API получит только право чтения.

- [ ] На отдельной локальной БД применить миграцию, seed fintraffic и проверить PK/FK, правила MMSI и SRID; применять миграцию один раз в pipeline, повторный запуск migration runner пропускает уже применённую версию по журналу; повторное выполнение самого SQL не является требованием.
- [ ] Проверить UPSERT для перестановок одной пачки, тайм-конфликта и трёх событий с точностью до секунд и миллисекунд. Один ключ даёт одну строку; старый bucket не откатывает; tie-break детерминирован; stale epoch отклоняется.
- [ ] Проверить, что искусственная ошибка в пачке откатывает позиции и статус целиком. Проверить TTL на 24 ч ровно и на 1 мс позже. Запустить `python -m pytest tests/integration/test_store.py` с PostGIS.

### Этап 3. Доступ к источнику и восстановление

Будущие файлы: `src/shadow_fleet/collector.py`, `src/shadow_fleet/settings.py`, `tests/test_collector.py`. Тестовый REST/MQTT transport с управляемыми часами и порядком доставки; без живой зависимости в CI.

- [ ] Воспроизвести SUBACK → MQTT раньше REST → commit. Сломанный снимок и пустой валидный снимок не очищают сохранённые строки.
- [ ] Проверить сценарии disconnect, 429 и Retry-After, переполнение, поздний callback, истечение heartbeat, рестарт. После сверки статус восстанавливается только для действующего epoch.
- [ ] Измерить очередь на синтетике 100 msg/s, 60 секунд; зафиксировать обработку и отбрасывания. Выполнить короткий ручной smoke Fintraffic с лимитами из дизайна; сохранить только счётчики. Запустить `python -m pytest tests/test_collector.py`.

### Этап 4. Чтение и контракт карты

Будущие файлы: `src/shadow_fleet/api.py`, `tests/integration/test_api.py`, `docs/api/v1.md`. Входы — bbox или ключ. Возвращаем зафиксированный JSON-контракт с единым as_of. Endpoint не обращается к поставщику.

- [ ] Проверить bbox, антимеридиан с точкой -180, cap 2 000, стабильный порядок, 400/404/503; фильтр TTL применяется независимо от уборки.
- [ ] Проверить согласованность полей source/state и items при параллельной записи; атрибуцию и отсутствие сырых полей. Запустить `python -m pytest tests/integration/test_api.py`.
- [ ] Записать p50/p95 для 100 запросов по синтетической проекции 5 000 ключей. Сравнить с предложенной целью ≤300 мс, сохранить окружение, запрос, размер ответа и результат.

### Этап 5. Карта, документация, приёмка

Будущие файлы: `web/src/map.ts`, `web/src/api.ts`, `web/src/details.ts`, `web/tests/map.spec.ts`, `docs/run-local.md`.

- [ ] Показать карту, карточку по клику, возраст и источник, понятное состояние «нет наблюдений в этой области». Использовать нейтральную подложку, пока права на тайлы не проверены.
- [ ] Проверить смену viewport при позднем ответе, stale-маркер и degraded без очистки экрана. Зафиксировать команду браузерных тестов в web package и запустить её.
- [ ] С нуля пройти локальный сценарий: запуск → снимок → обновление → потеря потока → восстановление → повторный запуск. Свести доказательства по R01–R08 и отдельно перечислить невыполненные проверки. Результат v0.1 не считается готовностью глобального продукта.

Дальнейшие этапы: сопоставление источников и identity, валидированная история, отдельный слой внешних утверждений, экспериментальные аномалии, затем публичное покрытие и эксплуатационная готовность.

## Дополнения после ревью

- [ ] Проверить clock_skew на сдвигах -1, 0, +60, +60.001 с; сверить БД и JSON.
- [ ] Перестановки идентичных REST/MQTT кандидатов дают одинаковые transport, precision, received_at и флаги; конфликт сохраняется после повторной доставки победителя.
- [ ] При непрерывном потоке bootstrap заканчивается по watermark; сообщение после границы применяется следующим batch, до границы — атомарно со снимком.
- [ ] Проверить отсутствие push после SUBACK, retained-only поток, дубликаты, зависшую запись, смерть владельца lock и второй экземпляр сборщика.
- [ ] Проверить bbox у ±180, нулевую ширину (180,-180), весь мир и точки на границах; нет повторных ключей.
- [ ] При отказе API карта остаётся видимой с явным временем последнего ответа; после восстановления устаревший запрос не перезаписывает актуальный.
